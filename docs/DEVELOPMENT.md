# Development guide

## Prerequisites

- Python 3.11+
- Git
- Docker with Compose (optional)

## Environment

```bash
python -m venv .venv
```

Activate the environment and install an editable development build:

```bash
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
```

Copy `.env.example` to `.env`. Keep `TRACEAID_ENABLE_LIVE_PROBES=false` while developing rules and UI features. Tests must not depend on a real OpenAI key or internet access.

## Run the application

```bash
uvicorn traceaid.main:app --reload --host 127.0.0.1 --port 8000
```

Useful local URLs:

- application: `http://localhost:8000`
- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- health: `http://localhost:8000/api/health`

## Test strategy

### Unit tests

Unit tests cover normalization, `curl` parsing, redaction, URL policy, deterministic rules, and artifact rendering. They should be fast, deterministic, and network-free.

```bash
pytest tests/unit
```

### Integration tests

Integration tests exercise FastAPI routes and boundaries between components. Use `respx` or dependency overrides for outbound HTTP and the OpenAI adapter.

```bash
pytest tests/integration
```

### Complete suite

```bash
pytest
pytest --cov-report=html
```

The second command writes a local report to `htmlcov/index.html`.

## Static checks

```bash
ruff check .
ruff format --check .
mypy src
pip-audit
```

To apply safe formatting and lint fixes:

```bash
ruff format .
ruff check . --fix
```

## Interactive demo and browser checks

```bash
python -m traceaid.static_demo --output site
python -m traceaid.static_demo --output site --check
npm ci
npx playwright install chromium
npm test
```

The Pages build uses only synthetic reports generated by the same Python service as the API. It ignores API keys and probe settings, uses relative assets, and makes no diagnosis API calls. Its evidence fields are read-only. The local application accepts custom evidence and reports real API errors without inventing a fallback diagnosis.

Playwright starts a static server on port 18767 and FastAPI on port 18768. On Windows, optionally set `TRACEAID_BROWSER_CHANNEL=chrome` to use installed Chrome and `TRACEAID_TEST_PYTHON` to the full path of your environment's Python executable. The default uses `python` and Playwright Chromium.

To update the documentation screenshots after a visible change:

```bash
node scripts/capture-demo.cjs
```

Use a fresh checkout/output directory for publication. The builder preserves unrelated files rather than deleting them.

## Adding a diagnostic rule

1. Start from concrete evidence: status, headers, response fields, latency, or a client error.
2. Pick one stable category and calibrated severity.
3. Explain why the evidence supports the likely cause; do not claim certainty without proof.
4. Provide ordered actions that a developer can verify.
5. Add positive, negative, redaction, and fallback tests.
6. Use only the normalized models so browser, CLI, and API behavior remain aligned.

Provider-specific advice should be guarded by provider-specific evidence. Generic failures should receive generic diagnostic steps.

## Changing the API

- Update Pydantic models and route tests together.
- Preserve safe defaults for `execute_probe` and `use_ai`.
- Regenerate/review `/api/openapi.json` behavior through integration tests.
- Update `docs/API.md`, README examples, and CLI behavior.
- Prefer a new versioned route for breaking public changes.

## Container checks

```bash
docker compose build
docker compose up
```

Verify the health endpoint, then confirm that the process runs as the non-root `traceaid` user and the application still works with the read-only filesystem.

## Release checklist

1. Run `make check` and `pip-audit`.
2. Build the wheel with `python -m build` if publishing an artifact.
3. Build and smoke-test the container.
4. Review documentation and `.env.example` against current settings.
5. Confirm fixtures, logs, and screenshots contain no real secrets.
6. Tag the release using semantic versioning and publish concise release notes.
